# 跨境订单录入管理后台开发说明 v1.2

日期：2026-11-05。菜单名称：跨境订单录入管理。

依据：当前本地管理后台原型 `admin-prototype/cross-border-order-management.html`、已集成的后台入口 `gift-admin-prototype.html?menu=crossBorder`，以及最新手机端原型（main `2f2672d` / Pages `627cc58`）。本文以本地后台为交互基线，不代表后台公网已同步本地变更。v1.1保留供追溯。

后台固定公网入口：https://moonqin800-sys.github.io/demomoon/gift-admin-prototype.html

手机端参考：https://moonqin800-sys.github.io/mobilemoon/cross-border-gift-prototype.html?v=627cc58

## 本次变更

- 统一最新详情结构：基本资料 → 本订单商品明细 → 上传凭证及识别结果对照。
- 上传凭证默认3张演示图，支持缩略图切换和放大；移除处理记录展示。
- AI识别值、提交值双栏完整展示订单与商品字段。
- 同步手机端统一上传识别、听数覆盖而非累加，以及无听数禁用赠品输入规则。
- 详情顶部以商品明细表替代品牌听数卡片，展示识别值听数和提交听数。
- 识别结果对照覆盖订单号、下单日期、每条商品的品牌、阶段、克数、听数，差异字段高亮。
- 详情展示提交时日期校验结果；上传提示最近一个月，当前提交窗口为含当天30天。历史订单不会因当前超过30天被标记不合法。
- 无筛选结果时阻止空文件导出并给出提示。

## 1. 定位与范围

用于运营、客服核对移动端已提交订单；建立KA、门店、上传人员与订单/商品明细的查询链路。此后台为根据最新业务推导的建议范围，用户已指定菜单名称，其余权限、导出及审计能力需需求评审确认。

本期原型含筛选、分页、详情、识别结果对照、CSV导出。后台不提供新增订单、直接编辑订单、删除正式订单、人工核销或强制绕过重复校验。业务如需纠错，另定义授权、原因、关联兑换状态及审计规则后实施。

## 2. 导航

现有后台新增一级菜单“跨境订单录入管理”，不替换礼品库、小票识别等既有模块。入口支持 ?menu=crossBorder，实际固定公网地址继续使用 gift-admin-prototype.html。新模块以同仓库HTML嵌入实现，仅是原型组织方式，正式开发采用项目既有路由与组件规范。

## 3. 查询列表

| 项目 | 定义 |
|---|---|
| 订单号 | 模糊匹配，字符串，不转数字 |
| KA | 全部/山姆/爱婴室/孩子王/沃尔玛/爱婴岛/盒马/天虹；正式来自权限内字典 |
| 门店 | 名称或编码 |
| 上传人 | 姓名或账号，不是消费者手机号 |
| 品牌 | 任一明细命中即返回整单 |
| 上传日期 | 起止日期，均含边界；开始不得晚于结束 |
| 是否人工修改 | 全部、是、否；是数据追溯标识，不是审核状态 |

列表列：订单号/下单日期、KA/门店、订单详情、上传人、上传时间、是否人工修改、查看详情。摘要按品牌名称+阶段+听数，多条顿号分隔；克数在详情和导出中保留。

默认上传时间倒序；原型每页5条，支持上一页/下一页，空结果展示空态。正式建议服务端分页并用主键保证同时间排序稳定。移动端近两个月限制不自动等于后台限制；后台查询保留期与最大查询跨度待确认。

## 4. 订单详情

基本资料：订单号、KA、下单日期、门店名称和编码、上传人员和账号、上传时间、是否人工修改、提交时日期校验。

商品表：位于订单基本资料下方，列为品牌、阶段、克数、识别值听数、提交听数；替代原“本订单品牌听数”卡片，截图右侧不再重复展示商品表。品牌、阶段、克数取最终提交值；两类听数按lineId匹配原始识别与最终明细，原始不存在时显示“—”。

听数按商品明细逐行对照，不按品牌合并，也不代表消费者剩余可兑换额度。完整字段修改仍在下方AI识别值与提交值板块展示。

提交时日期校验：原型使用上传时间作为提交时间示例，判断下单日期是否介于提交当天与29天前（含边界）。正式服务须保存提交时间、校验规则版本及校验结果，不应用当前日期重新评价历史订单。本次增加一笔较早提交的合法订单示例。

截图区：参考小票识别管理详情，展示“上传凭证”、图片数量、主预览图、缩略图、第N / 总数张和“查看放大图”。点击缩略图切换主图并高亮选中项；点击放大按钮打开图片弹框，关闭后保留原订单详情和选中图片。后台每笔订单默认提供3张示例凭证，初始选中第1张，支持切换和放大；正式组件按实际图片数组展示数量。此调整用于后台多图预览演示，移动端上传规则未作修改。原型图片由演示订单的原始识别数据生成，不是真实上传截图。正式从授权图片地址读取原图，补充图片失效重试，不得使用公开永久图片地址。

识别对照：AI原始结构化值与提交最终值按字段路径对应，多商品以lineId匹配。原型以左右两个独立板块展示“AI识别值”和“提交值”；两侧均完整展示订单号、下单日期，以及每条商品的品牌、阶段、克数和听数。提交侧以浅橙色标记与AI识别值不同的字段，不再逐行展示“是否人工修改”列；列表及订单基本资料中的该标识保留。正式应保留每笔已提交订单所对应的原始识别快照及最终提交快照；新一轮识别不能覆盖该订单的历史对照数据。新增/删除商品行也须保留变更记录（当前原型未演示增删对照）。

订单详情不展示“处理记录”标题及上传、识别、人工修正、提交成功的流程文字。

## 5. 导出

点击“导出筛选结果”导出当前筛选全部结果，而非当前页。原型CSV可下载；一条商品明细一行，订单主信息重复。

列顺序：KA、订单号、下单日期、门店、门店编码、上传人、上传账号、上传时间、品牌、阶段、克数G、听数、是否人工修改。当前导出“听数”为最终提交听数；新增详情对照列未自动增加到CSV。是否新增“识别值听数”导出列需确认。

正式建议使用XLSX并将订单号列写为文本，避免长数字精度损失；防止公式注入；空结果提示；大批量异步任务带有效期下载；导出范围必须受角色/KA/区域限制。记录导出人、筛选条件、条数和时间。是否包含消费者手机号待确认，本原型不包含。

## 6. 权限建议（待确认）

| 角色 | 范围 | 建议动作 |
|---|---|---|
| 运营管理员 | 授权活动/KA | 查询、详情、导出 |
| 区域负责人 | 授权区域/门店 | 查询、详情，导出单独授权 |
| 客服 | 授权订单 | 查询、详情 |
| 审计人员 | 授权范围 | 只读、审计记录 |

前端隐藏按钮仅用于体验，API必须强制鉴权；详情不可通过枚举orderId越权。图片访问与导出继承订单权限。后台不直接开放手机号/地址等无关信息。

## 7. 服务能力

- GET orders：接收筛选及页码，返回total和列表摘要。
- GET orders/{id}：主单、商品行、授权截图、原始识别与最终值。
- POST order-exports：接收筛选条件创建导出任务。
- GET order-exports/{id}：返回进度、失败原因、限时下载链接。

路径仅示意。建议使用统一错误码：无权限、参数错误、日期区间错误、记录不存在、图片不可用、导出失败。筛选输入参数化处理。商品筛选与分页需避免一对多join导致重复订单/总数错误。

## 8. 关联移动端规则

KA+订单号共同识别一笔订单；列表不得按订单号全局合并。示例数据故意包含山姆和爱婴室相同订单号，验证跨KA合法。

详情只展示提交成功数据；识别失败/草稿并非已提交订单。若需要异常任务工作台，应新增独立模块及状态定义，不混入“否”标识。

手机号验证仍是手机演示；后台上传人员应从FMC身份获取，不采用输入手机号作为录入账号。展示的最终听数用于追溯，资格/核销结果属于兑换服务，不能据“已录入”推导“已兑换”。

### 最新移动端联动边界

- 上传区最新提示为“请上传全部订单截图后统一识别。再次识别将覆盖原听数，不会累加。”，另起一行“仅支持最近一个月的订单截图。”；提交仍按含当天近30天校验。后台查询不默认限制最近一个月；移动端本人查询仍为近两个月。
- 选择品牌切换对应赠品，各品牌数量保留；当前品牌无AI识别听数或为0时，下一步及该品牌赠品数量输入框均禁用。重新识别回填后某品牌听数变为0，清空其赠品数量；禁用的赠品不进入二维码弹框。后台按最终明细追溯品牌听数，不新增未确认的赠品配置功能。
- 二维码在移动端以弹框展示，汇总跨品牌赠品并支持横滑。后台本模块仍是订单查询，不新增二维码签发、核销、赠品申请记录或库存管理能力。
- 是否人工修改以原始识别与提交最终值的差异为准；否不等于审核通过，是不等于识别失败。该字段由服务端计算，不能信任前端标记。

### 识别批次与历史数据边界

最新用户提示要求上传完整截图后统一识别，不支持二次识别叠加听数。当前手机原型在订单列表“提交”成功时，按本批次商品汇总覆盖赠品页品牌听数；点击“上传并开始识别”仅生成待核对结果，并不立即回填赠品页。新批次提交失败时不覆盖原有品牌听数。

例如：上一批港版皇家9听，新批提交港版皇家3听，赠品页展示3听，不是12听；新批没有港版有机皇家时，该品牌听数为空且赠品输入禁用。此覆盖针对当前赠品选择上下文，不表示删除或修改历史已提交订单。后台继续按各订单自己的提交快照查询，避免把当前赠品页总数写回历史订单。

建议正式数据关联保留batchId、orderId、lineId、recognitionTaskId及原始/最终字段快照；技术字段名称以现有服务约定为准。手机号不能替代上传人员身份，品牌汇总不能替代订单明细。批次与兑换申请如何关联、再次识别是否可在已生成申请后进行，仍需评审确认。

## 9. 验收

1. 现有菜单正常，新菜单标题和面包屑准确，直达链接可用。
2. 多字段组合筛选正确；重置恢复；日期逆序明确提示。
3. 同订单号跨KA展示两条；品牌筛选返回含该品牌的整单。
4. 分页不重复/漏单，边界按钮不可用，空结果无假数据。
5. 详情字段与列表一致；每条商品独立展示克数、听数；识别对照可追溯。
6. 导出包含筛选全量商品明细，中文正常，超长订单号不丢精度（正式导出要求）。
7. 无权限用户不能查详情、导出或访问原图；服务端验证数据范围。
8. 网络失败、无图片、导出失败均有明确可重试反馈（正式开发要求）。
9. 三个品牌均可筛选得到对应示例；多品牌订单按明细命中返回整单。
10. 顶部商品明细表按lineId正确展示识别值听数与提交听数，例如2听→3听；不再显示品牌汇总卡片或重复商品表。
11. 人工修改订单展示全部字段及高亮差异；未修改订单所有字段一致。
12. 历史订单按提交当时日期窗口展示校验结果，不因今天距下单超过30天而误报。
13. 空筛选结果点击导出，提示“暂无可导出的订单，请调整筛选条件”，不生成空文件。

14. 打开详情默认展示第1 / 3张，点击第3张切换主图、选中边框及计数；放大图对应当前图片，关闭保留详情和选择。
15. 双栏分别显示“AI识别值”“提交值”，均含订单号、下单日期、商品品牌、阶段、克数和听数；只有提交侧差异字段高亮。
16. 订单详情无“处理记录”标题或流程文字。
17. 手机端新批次提交成功后听数覆盖、不累加；后台已有订单的原始/最终字段快照保持原样（正式联调验收）。

## 10. 原型限制与待确认

原型12笔数据为虚构，仅内存筛选和CSV下载；无真实登录、API、OCR、审计和权限执行。截图为生成的演示凭证图片。正式需确认后台数据范围、保留期限、是否允许人工纠错、导出权限、消费者信息使用目的。日期口径必须与移动端最终规则一致。


### 仍需确认的开发边界

- 手机端一单一图与后台默认3张演示图属于不同演示配置，不能仅凭后台多图示例推导已开放同单补图；正式截图与订单关联方式需冻结。
- “最近一个月”提示当前按含当天30个自然日执行，是否需要滚动日历月仍需明确。
- 新批次听数降低但仍大于0时，原型保留该品牌赠品数量；正式额度复核、超额提示和库存校验仍需接入。
- 人工新增/删除商品行的识别对照展示、导出是否增加识别值听数、批次和兑换申请关联需确认。
- 实际上传图片、真实AI识别、服务端鉴权、审计及持久化未接入；示例图片与示例校验结果不等于生产数据。

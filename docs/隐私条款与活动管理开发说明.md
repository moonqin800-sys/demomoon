版本：v1.1  
日期：2026-08-09

## 1. 背景与目标

本次开发围绕 E-learning、iDream、会员服务等注册页面隐私条款整改，补齐后台对“渠道隐私条款、条款文件、用户同意记录、活动注册渠道关联”的维护能力。

核心目标：

- 后台可按渠道维护不同条款，不再依赖统一外链。
- 活动配置可指定“注册隐私条款渠道”，前端注册页据此展示对应渠道条款。
- 条款正文改为 PDF 文件上传维护，并按渠道、条款类型保存。
- 只有“隐私政策”类型维护版本号；儿童个人信息处理规则、个人信息收集清单、个人信息共享清单、服务协议不维护版本号。
- 发布条款时展示二次确认；隐私政策发布时版本号按 `V主版本.小版本` 格式自动递增，其他条款发布时仅更新当前有效文件。
- 用户同意条款后记录 OpenID、会员ID、渠道、条款类型、版本号、创建时间；非隐私政策类型的版本号为空。
- 后台默认打开“隐私条款管理 / 隐私条款维护”，方便合规运营优先处理。

- 活动名称、活动代码、活动分类、活动类型、开始时间、截止时间、注册隐私条款渠道不能为空。
- 截止时间不得早于开始时间，建议后端强校验。
- 若同时填写“物流填写截止天数”和“物流填写结束时间”，业务需明确优先级；建议优先使用“物流填写截止天数”。
- 注册隐私条款渠道必须使用统一枚举，避免前端无法匹配条款。

### 5.2 列表字段

| --- | --- | --- | --- |

### 5.4 版本号规则

版本号只适用于条款类型为“隐私政策”的记录。

| 条款类型 | 是否维护版本号 | 发布行为 |
| --- | --- | --- |
| 隐私政策 | 是 | 发布时自动递增小版本号，例如 `V1.0 -> V1.1` |
| 儿童个人信息处理规则 | 否 | 发布时不生成版本号，仅更新当前有效 PDF |
| 个人信息收集清单 | 否 | 发布时不生成版本号，仅更新当前有效 PDF |
| 个人信息共享清单 | 否 | 发布时不生成版本号，仅更新当前有效 PDF |
| 服务协议 | 否 | 发布时不生成版本号，仅更新当前有效 PDF |

前端交互要求：

- 新增草稿默认可选“隐私政策”，展示版本号字段。
- 当运营把条款类型切换为非隐私政策时，隐藏“当前发布版本”和“本次发布版本号”。
- 非隐私政策类型的列表、历史版本、发布确认中均不展示实际版本号。
- 隐私政策版本号格式统一为 `V主版本.小版本`，例如 `V1.0`、`V1.1`、`V1.2`。

后端实现要求：

- `policy_type = privacy` 时，`version` 必填并由后端发布接口递增小版本。
- `policy_type != privacy` 时，`version` 应为空或 `null`，不得生成伪版本号。
- 版本递增必须以后端事务保证，避免并发发布导致版本冲突。

### 5.5 发布规则

- 点击“发布”时必须弹出二次确认。
- 隐私政策二次确认文案需明确“发布后系统将自动生成新版本”。
- 非隐私政策二次确认文案需明确“该条款类型不维护版本号，发布后仅更新当前有效文件”。
- 发布成功后状态改为“已发布”，更新时间刷新。
- 发布操作写入历史记录。

### 5.6 历史版本弹框

| 字段 | 说明 |
| --- | --- |
| 渠道 | 条款所属渠道 |
| 条款类型 | 条款业务类型 |
| 版本 | 仅隐私政策有版本号；其他条款类型为空或 `-` |
| 创建时间 | 版本创建或发布时间 |

## 6. 隐私条款记录

页面定位：查询用户同意隐私条款的留痕记录，用于审计追溯。

### 6.1 查询条件

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| OpenID / 会员ID | 文本 | 支持 OpenID、会员ID 模糊查询 |
| 渠道 | 下拉 | 会员服务小程序、E-learning、iDream、妈妈班、路演 |
| 隐私条款类型 | 下拉 | 隐私政策等类型 |
| 版本 | 文本 | 仅对隐私政策记录有效；非隐私政策记录版本为空 |
| 创建时间 | 日期 | 按同意记录创建日期查询 |

### 6.2 列表字段

| 字段 | 说明 |
| --- | --- |
| openID | 用户 OpenID |
| 会员ID | 用户会员编号 |
| 渠道 | 用户同意的条款渠道 |
| 隐私条款类型 | 用户同意的条款类型 |
| 隐私政策版本 | 仅隐私政策有版本号；其他条款类型为空或 `-` |
| 创建时间 | 用户同意时间 |

### 6.3 记录生成规则

- 新注册用户在注册成功且勾选同意后写入记录。
- 记录需绑定渠道、条款类型、同意时间、OpenID、会员ID。
- 若同意的是隐私政策，必须记录当时的隐私政策版本号。
- 若同意的是其他条款类型，版本号为空或 `null`。
- 同一用户可存在多条记录，用于保留不同渠道、不同条款类型、不同时间的确认历史。

## 7. 前端注册页调用规则

活动进入注册页时：

1. 前端根据活动代码查询活动配置。
2. 从活动配置中读取 `注册隐私条款渠道`。
3. 根据渠道查询该渠道当前已发布的隐私政策及相关条款。
4. 注册页展示对应渠道条款，不再统一跳转外链。
5. 用户勾选并注册成功后，提交同意记录。

建议注册页至少展示：

- 隐私政策。
- 儿童个人信息处理规则，若当前渠道涉及未成年人信息。
- 个人信息收集清单或共享清单，若当前渠道配置了关联条款。
- 服务协议，若注册场景要求。

存量用户进入活动页时：

- 系统按用户历史同意版本和当前已发布隐私政策版本比较。
- 仅隐私政策参与版本高低判断。
- 若用户对应渠道的历史隐私政策版本低于当前版本，前端弹窗要求重新确认。
- 非隐私政策类型不做版本高低判断，可按文件更新时间或运营策略另行处理。
- 当前原型已移除后台“老用户版本更新弹窗文案”维护项，弹窗文案建议由前端统一模板或配置中心统一维护。

## 8. 接口建议

### 8.1 活动管理

查询活动列表：

```http
GET /api/admin/activities
```

请求参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| keyword | string | 否 | 活动名称或活动代码 |
| endAfter | string | 否 | 结束时间晚于，格式 `YYYY-MM-DD` |
| pageNo | number | 否 | 页码 |
| pageSize | number | 否 | 每页条数 |

保存活动：

```http
POST /api/admin/activities/{activityId}
```

核心请求字段：

```json
{
  "activityName": "RKA无导门店买赠活动",
  "activityCode": "B_RKAMDMD_A_260801",
  "category": "buyfree_cam",
  "activityType": "buyfree_cam",
  "startAt": "2026-08-01",
  "endAt": "2026-09-01",
  "logisticsDeadlineDays": 46,
  "logisticsEndAt": "2026-09-01",
  "privacyChannel": "member",
  "workStartAt": null,
  "workEndAt": null,
  "logisticsKeyword": "",
  "drawKeyword": "",
  "intro": "",
  "manualFileId": "FILE-001"
}
```

### 8.2 隐私条款维护

查询条款列表：

```http
GET /api/admin/privacy-policies
```

保存草稿：

```http
POST /api/admin/privacy-policies

```

```json
{
  "channel": "member",
  "policyType": "privacy",
  "title": "会员服务小程序隐私政策",
  "version": "V1.2",

  "status": "draft",
  "scene": "会员服务小程序注册、条款中心"

```

非隐私政策类型保存示例：

```json
{
  "channel": "member",
  "policyType": "service",
  "title": "会员服务小程序服务协议",

  "pdfFileId": "FILE-SERVICE-001",

```

```json
  "version": "V1.3",
  "status": "published",
  "publishedAt": "2026-08-09 15:30"

```

非隐私政策发布响应建议：

```json
{
  "policyId": "PP-MEMBER-SERVICE",
  "channel": "member",
  "policyType": "service",
  "version": null,
  "status": "published",
  "publishedAt": "2026-08-09 15:30"

```

查询历史记录：

```http
GET /api/admin/privacy-policies/{policyId}/versions
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |

## 11. 验收用例

活动管理：

- 可进入一级菜单“活动管理”。
- 可按关键词查询活动名称、活动代码。
- 可按结束时间筛选活动。
- 点击编辑可打开活动编辑弹框。
- 未填写“注册隐私条款渠道”时保存失败。
- 填写必填字段后保存成功，列表同步刷新。

隐私条款维护：

- 默认打开后台入口时选中“隐私条款维护”。
- 可按关键词、渠道、条款类型、发布状态筛选。
- 点击新增草稿打开弹框。
- 条款正文只能选择 PDF 文件。
- 条款类型为“隐私政策”时，弹框展示“当前发布版本”和“本次发布版本号”。
- 条款类型切换为非隐私政策时，弹框隐藏版本号字段。
- 非隐私政策类型在列表“当前版本”展示为空或 `-`。
- 点击发布先展示二次确认。
- 隐私政策确认发布后版本号自动递增。
- 非隐私政策确认发布后不生成版本号，仅更新状态和 PDF。
- 点击历史版本可查看渠道、条款类型、版本、创建时间；非隐私政策版本为空或 `-`。
- 弹框中不再展示“老用户版本更新弹窗文案”。

隐私条款记录：

- 可按 OpenID/会员ID、渠道、条款类型、版本、创建时间查询。
- 列表字段与原型一致。
- 隐私政策同意记录必须有版本号。
- 非隐私政策同意记录版本号为空或 `-`。
- 用户注册同意后可生成对应记录。

前端注册链路：

- 活动注册页根据活动的 `privacyChannel` 获取对应渠道条款。
- 注册页展示当前渠道已发布条款 PDF。
- 用户同意后写入条款同意记录。
- 存量用户仅按隐私政策版本判断是否低版本并触发重新确认。

## 12. 研发注意事项

- PDF 文件需走统一文件上传服务，并返回 `fileId`、`fileName`、访问 URL。
- 发布接口必须后端原子化处理隐私政策版本号小版本递增，避免并发发布导致版本冲突。
- 非隐私政策类型不得生成版本号，避免审计口径混乱。
- 用户同意记录不可物理删除，审计场景需长期留存。
- `privacyChannel` 是活动注册页与隐私条款维护之间的关键关联字段，前后端字段枚举必须一致。
- 如果不同活动共用同一渠道，注册页展示同一渠道当前已发布条款。
- 若某渠道缺少已发布隐私政策，注册页应阻断注册并提示运营补充配置。
- 后台列表中的版本号筛选对非隐私政策记录无效，后端需兼容 `version is null` 的数据。

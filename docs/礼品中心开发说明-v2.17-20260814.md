# 礼品中心开发说明

版本：v1.1  
日期：2026-08-14  
对应原型：`gift-admin-prototype.html` / `gift-admin-prototype-v2.17-20260814.html`  
公网入口：<https://moonqin800-sys.github.io/demomoon/gift-admin-prototype.html>  
礼品库直达：<https://moonqin800-sys.github.io/demomoon/gift-admin-prototype.html?nav=library>

## 1. 背景与目标

礼品中心用于统一承接买赠活动相关礼品资料和活动礼品展示配置。当前业务口径已经明确：礼品库数据不是后台手工新增，而是来自上游系统同步；后台主要负责素材补充、状态维护、活动维度的展示自定义和消费者端展示预览。

建设目标：

1. 礼品主数据统一从上游同步，避免运营重复录入礼品 code、礼品名称等核心字段。
2. 礼品素材集中维护，减少活动页、我的礼品、礼品详情多处展示不一致。
3. 活动礼品配置只处理活动维度关系和素材自定义，不回写礼品库默认资料。
4. 为消费者端活动页、我的礼品页、礼品详情页提供稳定数据来源。

## 2. 功能范围

| 模块 | 页面标识 | 本期能力 |
| --- | --- | --- |
| 礼品库 | `library` | 查询礼品、同步礼品、编辑补充信息、维护素材、预览消费者端展示 |
| 活动礼品配置 | `activity` | 选择活动、同步活动礼品数据、查看绑定礼品、活动内素材自定义 |

不在本期范围：

- 后台手工新建礼品主数据。
- 礼品 code、礼品名称人工修改。
- 活动礼品列表中的人工排序、展示时间、活动内状态配置。
- 批量停用活动礼品。

## 4. 礼品库

## 4.1 页面定位

礼品库是礼品主数据和默认展示素材的集中维护入口。礼品 code、礼品名称、礼品类型、品牌、规格等基础字段由上游系统同步；运营可在后台补充客服电话、别名、图片、视频、状态等展示相关信息。

## 4.2 查询条件

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 关键词 | 文本输入 | 支持礼品 code、礼品名称、品牌模糊查询 |
| 礼品类型 | 下拉 | 全部类型、实物礼品、红包礼品、虚拟礼品 |
| 状态 | 下拉 | 全部状态、启用、草稿、停用 |
| 品牌 | 下拉 | 全部品牌、Friso、Hape、SXJF 等 |

交互规则：

- 输入或选择筛选条件后，列表按条件过滤。
- 当前原型已去掉“重置”按钮，研发如保留重置需单独确认。

## 4.3 列表字段

| 字段 | 说明 |
| --- | --- |
| 礼品信息 | 展示礼品缩略图、礼品名称、礼品 code、礼品别名 |
| 类型 | 实物礼品、红包礼品、虚拟礼品 |
| 品牌 | 礼品所属品牌 |
| 素材状态 | 完整、缺详情图、缺活动图等 |
| 客服电话 | 礼品详情页展示电话 |
| 状态 | 启用、草稿、停用 |
| 更新时间 | 最近维护时间 |
| 操作 | 编辑、预览 |

已移除内容：

- 顶部统计卡片：礼品总数、启用礼品数、待补素材、活动绑定。
- 列表操作“复制”。

## 4.4 同步礼品

入口文案：`同步礼品`

业务规则：

- 礼品数据来自上游系统同步，不允许运营在后台手工创建礼品主数据。
- 同步时应拉取礼品 code、礼品名称、礼品类型、品牌、规格等基础字段。
- 同步完成后，已存在礼品按礼品 code 做更新；新增礼品写入礼品库。
- 如上游礼品名称变更，应以后端同步结果为准，但需保留操作日志。
- 同步失败需给出失败提示，并记录失败原因，便于运营或研发排查。

建议同步结果字段：

| 字段 | 说明 |
| --- | --- |
| total_count | 本次上游返回总数 |
| created_count | 新增礼品数 |
| updated_count | 更新礼品数 |
| skipped_count | 跳过数量 |
| failed_count | 失败数量 |
| failed_items | 失败礼品明细和原因 |

## 4.5 礼品编辑弹框

礼品编辑采用居中弹框形式，用于维护礼品展示资料，不用于修改主数据核心字段。弹框内保留“基础信息 / 展示素材 / 操作记录”三个 Tab。

### 基础信息

| 字段 | 是否可编辑 | 说明 |
| --- | --- | --- |
| 礼品 code | 否 | 上游同步字段，全局唯一 |
| 礼品名称 | 否 | 上游同步字段 |
| 礼品别名 | 是 | 消费者端可展示的短标题 |
| 礼品类型 | 建议只读 | 来自上游，若需修改需有独立权限 |
| 品牌 | 建议只读或受控编辑 | 来自上游或品牌字典 |
| 规格 | 是 | 可用于礼品详情展示 |
| 客服电话 | 是 | 礼品详情页展示 |
| 状态 | 是 | 草稿、启用、停用 |
| 备注 | 是 | 内部运营说明 |

强校验：

- 保存接口不得允许修改礼品 code。
- 保存接口不得允许修改礼品名称。
- 前端只读只是体验约束，后端必须再次校验。

### 展示素材

| 素材 | 使用场景 | 建议规则 |
| --- | --- | --- |
| 主图 | 礼品库列表、我的礼品页 | JPG/PNG，建议 400x300 |
| 活动展示图 | 活动页“请选择赠品”卡片 | JPG/PNG，建议按活动页卡片比例校验 |
| 详情图 | 礼品详情页或弹窗 | 支持长图，需限制大小 |
| 物料图 | 线下物料、运营下载 | 可选 |
| 视频地址 | 礼品详情视频展示 | URL 或上传后资源地址 |

素材规则：

- 启用礼品前建议校验主图和活动展示图完整。
- 素材状态可由系统根据必填素材自动计算。
- 图片上传需限制格式、大小、宽高比例。

## 5. 活动礼品配置

## 5.1 页面定位

活动礼品配置用于按活动维护礼品绑定关系。该页面不再作为“添加礼品”的人工录入口，而是从活动或上游系统同步当前活动下的礼品数据。

## 5.2 活动选择

页面顶部先选择活动：

| 字段 | 说明 |
| --- | --- |
| 活动 | 活动名称下拉 |
| 活动 code | 选中活动后展示 |
| 活动时间 | 选中活动后展示 |
| 已绑定礼品 | 当前活动绑定礼品数量 |
| 前端状态 | 生效中、未开始、已结束等 |

规则：

- 必须先选择活动，再点击“同步数据”。
- 未选择活动时点击同步，应提示“请先选择活动”。

## 5.3 同步数据

入口文案：`同步数据`

交互规则：

- 点击后不展示具体“添加绑定”弹框。
- 页面只需要轻提示：`同步中`、`同步完成`。
- 同步完成后刷新活动礼品列表和已绑定礼品数量。

后端规则：

- 根据活动 code 拉取当前活动关联礼品。
- 按 `activity_code + gift_code` 判断是否已存在。
- 已存在关系可更新同步时间或状态，不重复创建。
- 新增关系写入活动礼品关系表。
- 上游已移除的礼品如何处理需业务确认，建议默认停用或保留历史，不物理删除。

## 5.4 活动礼品列表

| 字段 | 说明 |
| --- | --- |
| 礼品信息 | 礼品图片、名称、code、默认别名 |
| 活动内素材自定义 | 展示是否配置产品别名、主图、活动展示图自定义 |
| 操作 | 素材自定义、移除/解绑 |

已移除字段：

- 排序。
- 展示时间。
- 状态。

已移除操作：

- 批量停用。

## 5.5 素材自定义

原型文案：`素材自定义`

页面含义：同一个礼品可绑定多个活动。活动内如需特殊展示，可在当前活动维度覆盖部分展示素材，但不影响礼品库默认资料。

| 字段 | 规则 |
| --- | --- |
| 产品别名 | 可编辑，不填则继承礼品库别名或礼品名称 |
| 主图自定义 | 开启后当前活动使用活动级主图 |
| 活动展示图自定义 | 开启后当前活动页使用活动级展示图 |

展示优先级：

1. 当前活动的素材自定义。
2. 礼品库默认素材。
3. 系统兜底占位内容。

保存规则：

- 保存后仅影响当前活动。
- 不回写 `gift_master` 或礼品库默认素材。
- 需记录操作日志，包含活动 code、礼品 code、修改前后内容。

## 6. 消费者端读取规则

| 场景 | 数据来源 | 优先级 |
| --- | --- | --- |
| 活动页礼品卡片 | 活动礼品关系 + 礼品库 | 活动内活动展示图 > 礼品库活动展示图 |
| 活动页礼品名称 | 活动礼品关系 + 礼品库 | 活动内产品别名 > 礼品库别名 > 礼品名称 |
| 我的礼品页 | 礼品库 | 礼品库主图、礼品名称或别名 |
| 礼品详情页 | 礼品库 | 详情图、视频地址、客服电话 |

关键约束：

- 活动内自定义仅当前活动生效。
- 我的礼品页原则上使用礼品库默认资料，不读取某个活动的自定义素材，除非业务明确要求按来源活动展示。
- 已停用礼品是否在历史订单、我的礼品中展示，需要以后端订单状态和履约规则判断。

## 9. 关键校验

| 场景 | 校验规则 |
| --- | --- |
| 同步礼品 | 上游返回 gift_code 为空时拒绝入库 |
| 保存礼品 | gift_code、gift_name 不允许被修改 |
| 启用礼品 | 主图、活动展示图、客服电话建议完整 |
| 上传素材 | 校验文件类型、大小、尺寸比例 |
| 同步活动礼品 | 必须传 activity_code |
| 素材自定义 | 必须存在 activity_code + gift_code 关系 |
| 移除活动礼品 | 如已有用户领取记录，不建议物理删除 |

## 10. 验收标准

礼品库：

- `?nav=library` 打开后默认选中「礼品库」菜单。
- 礼品库列表支持按关键词、类型、状态、品牌查询。
- 页面按钮为“同步礼品”，不出现“新增礼品”。
- 礼品 code、礼品名称在编辑弹框不可修改。
- 列表不出现“复制”操作。
- 保存礼品资料后，素材状态、客服电话、状态、更新时间正确更新。

活动礼品配置：

- 必须先选择活动，再点击“同步数据”。
- 同步数据只展示“同步中 / 同步完成”轻提示，不展示具体添加绑定弹框。
- 列表字段只保留礼品信息、活动内素材自定义、操作。
- 页面不出现批量停用。
- “素材自定义”可修改产品别名，并可配置主图、活动展示图是否使用活动级覆盖。
- 自定义保存后只影响当前活动，不影响礼品库默认资料。

消费者端联动：

- 活动页读取活动礼品关系和活动级自定义。
- 我的礼品页读取礼品库默认主图和名称。
- 礼品详情读取详情图、视频地址、客服电话。

## 11. 风险与待确认

| 问题 | 建议 |
| --- | --- |
| 上游同步字段未最终确认 | 开发前确认礼品 code、名称、类型、品牌、规格、状态字段映射 |
| 上游删除礼品如何处理 | 建议本系统保留历史，仅标记停用或失效 |
| 活动礼品同步差异策略 | 明确新增、更新、移除、失败四类结果 |
| 礼品素材审核 | 如素材直接影响线上展示，建议增加发布或审核状态 |
| 历史订单展示 | 已领取礼品应保留领取时快照，避免后续改名改图影响历史记录 |

# AI识别查询与客诉处理原型

依据：项目《IQR活动客诉流程优化 业务流程 update 20261030》及查询页面截图。

入口：gift-admin-prototype.html?menu=aiQuery；独立页面：ai-recognition-query.html。

## 已实现
- 截图中全部查询条件、默认清空时间、重置、空结果、日期与手机号校验、分页和明细。
- 明细展示会员、活动、罐码、最近结果与识别历史。
- 集罐礼审核通过后可客诉处理：自动填充罐码、必填备注、选填附件、罐码可用性检查、补录资格/扫码1罐/积分及操作记录。
- 每位消费者集罐礼只可处理一次，提交期间禁止重复操作。
- 全活动AI恢复次数与原因留痕；Ebuy罐码信息同步反馈。

## 规则与待确认项
- 来源明确：时间默认清空；客诉目前仅集罐礼；AI罐码审核通过；自动填充码；备注；附件选填；校验可用性；补录扫码、增加1罐和积分；每位消费者仅一次；保留客服记录；所有活动支持恢复AI次数。
- 演示建议：每次恢复1次，备注必填，附件类型与10MB限制；正式恢复额度/上限、附件限制、权限、积分值、刷新时间待确认。
- WEDO增加资格后自动添加积分属于项目材料中的联动要求，本次以结果展示覆盖，未修改其他资格后台。
- 解绑、注销为材料讨论事项，未纳入本次原型。

## 验证与边界
- 两个HTML的JavaScript语法检查通过。
- 浏览器确认后台入口可加载，客诉提交成功生成操作记录，原客诉按钮变为禁用，显示每位消费者仅可一次。
- 均为虚构数据与内存交互；刷新即重置。无真实AI、Ebuy、资格、扫码、积分接口或持久化；附件仅记录文件名。
- 正式实现须服务端校验权限、消费者维度幂等、罐码占用；资格/扫码/积分跨系统失败需明确重试与对账方案，避免重复增加。
- 尚未提交或推送Git，也未更新公网。
